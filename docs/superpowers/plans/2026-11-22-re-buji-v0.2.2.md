**Tech Stack:** 計画 16 と同じ。依存は増やさない。

**Spec:** `docs/superpowers/specs/2026-11-05-re-buji-design.md`（3 従業員の登録、5 連絡と返事、6.5 記録の削除、8 リリース）

**前の計画：** `docs/superpowers/plans/2026-11-21-re-buji-v0.2.1.md`（PR #19 でマージ済み。v0.2.1 はリリース済み）。直すのは次の 5 件。作者が 2026-11-22 に選んだ。

## Global Constraints

- 計画 1〜16 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、SQLite の PRAGMA、UTC の時刻の文字列、名前空間、`.htaccess`
  - `setUp` / `tearDown` を使わない。テストでは、日付に依る値に `FrozenClock` を使う
  - コミットメッセージの末尾に `Co-Authored-By` を付ける
  - Psalm errorLevel 1、Pint
  - `src/php-version.php`、`public/index.php`、`bin/cron.php` は PHP 5.5 以降で読める構文のまま（このタスクでは触らない）
  - SQL は SQLite と MySQL の両方で動く書き方にする
- DB の形は変えない（マイグレーションを足さない）
- 今ある CSV（見出しが「ID」のもの）は、そのまま取り込める
- 画面とエラーの文言は、各タスクに書いたとおりにする。書いていない文言は変えない（取り込みのエラーの「ID は数字で…」「ID 999 の人はいません。」などは今のまま）

## Review Focus

- 答えも自動応答も無い連絡を、まとめていた地震を消す → 今までどおり「まとめた先の地震の記録を消しました」と出る（Task 1）
- 前の版で書き出した CSV（見出しが「ID」）を取り込む → そのまま取り込める（Task 2）
- 見出しの先頭が「ID」でも「従業員ID」でもない → 新しい見出し（「従業員ID」で始まる）を示すエラー（Task 2）
- ID の書き方が違う行が、ほかの行と同じアドレスを持つ → ID のエラーだけを出し、アドレスの重なりは言わない（Task 3）
- 「山田 　」のように、呼び名の後ろに全角の空白がある → 後ろの空白だけが除かれる（Task 4）
