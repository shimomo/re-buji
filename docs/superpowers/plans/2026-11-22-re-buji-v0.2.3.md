## Global Constraints

- 計画 1〜17 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、`setUp` / `tearDown` を使わない、コミットメッセージの末尾に `Co-Authored-By`、Psalm errorLevel 1、Pint
  - `src/php-version.php`、`public/index.php`、`bin/cron.php` は触らない
- DB の形は変えない（マイグレーションを足さない）
- zip の中身（ファイル、権限、順）は変えない。変えるのは各項目の時刻だけ
- 画面の文言は、各タスクに書いたとおりにする

## Review Focus

- 同じコミットから、時間をおいて 2 回 zip を作る → sha256 が同じ（Task 1）
- 新しいコミットを足してから zip を作る → 時刻が新しいコミットのものになる（Task 1）
- ID が読めない行のアドレスが、DB のほかの人のものでもある → 今どおり、その行についてはアドレスのエラーを出さない（Task 2）
- 送り主に `"` や `<` が入っている → 今どおり変換して読み上げの名前にする（Task 3）
- 送り主が空白だけ → 空と同じに扱う（Task 3）

### Task 1：同じコミットから同じ zip を作る

**Files:**
- Modify: `build-files/zip.php`、`bin/build-release.sh`、`.claude/skills/releasing-re-buji/SKILL.md`
- Test: `tests/BuildZipTest.php`

**Interfaces:**
- `php build-files/zip.php SOURCE TARGET MTIME`：3 つ目の引数を足す（Unix 時刻の整数。必須）。すべての項目（フォルダとファイル）の時刻を `ZipArchive::setMtimeName()` で MTIME にする。数字でなければ、今の使い方の文に `<mtime>` を足したものを出して `exit(1)`
- 使い方の文：`Usage: php build-files/zip.php <source directory> <target zip> <mtime>`
- `bin/build-release.sh`：`git -C "$root" log -1 --format=%ct HEAD` を MTIME として渡す（`git archive HEAD` の中身と同じコミットの時刻）
- スキル：
  - 手順 4 の「足したファイル」の diff を `git diff --stat --diff-filter=A v{前の版} HEAD -- src templates public migrations bin ':!bin/release.sh' ':!bin/build-release.sh'` にする（zip に入らないものを外す）
  - 手順 7 に「publish が出す sha256 が、手順 5 で見せたものと違えば、そのことを作者に伝える（同じコミットからは同じ zip ができるので、違うのは何かがおかしいとき）」を足す

- [ ] **Step 1: 失敗するテストを書く**

```php
// BuildZipTest
#[Test] public function makesTheSameZipFromTheSameFilesAtAnyTime(): void
// 一時ディレクトリに app/a.txt と app/sub/b.txt を作る
// zip.php app one.zip 1700000000 → touch で a.txt の時刻を 1 時間後にする → zip.php app two.zip 1700000000
// → one.zip と two.zip の sha256 が同じ（Review Focus）
// → ZipArchive で開いた two.zip の各項目の statIndex()['mtime'] が、どれも 1700000000

#[Test] public function asksForTheTime(): void
// zip.php app three.zip（3 つ目なし）→ 終了コード 1、出力に 'Usage: php build-files/zip.php <source directory> <target zip> <mtime>'
```

今の `noEntryIsWritableByTheGroupOrOthers` の `build()` も、3 つ目の引数（例：`1700000000`）を渡すように直す。

- [ ] **Step 2: 失敗を確かめる**

Run: `vendor/bin/phpunit --filter BuildZipTest`
Expected: 2 つの新しいテストが FAIL（時刻が今の時刻、3 つ目なしでも作れる）

- [ ] **Step 3: 実装する**

上の Interfaces のとおり。zip.php と build-release.sh を直し、スキルの 2 か所を書き換える。

- [ ] **Step 4: 通ることを確かめる**

Run: `vendor/bin/phpunit`、`vendor/bin/psalm --no-progress`、`vendor/bin/pint --test`
Expected: OK、No errors found、passed

手で：コミットした後に `bin/build-release.sh 0.2.2` を 2 回（間を 2 秒以上あけて）動かし、sha256 が同じであること（Review Focus）。スキルの diff のコマンドを `v0.2.1 HEAD` で動かし、`bin/release.sh` が出ないこと

- [ ] **Step 5: コミット**

```bash

git commit -m "fix: build the same release zip from the same commit, so check and publish show one hash"
```
