## Global Constraints

- 計画 1〜10 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、SQLite の PRAGMA、UTC の時刻の文字列、名前空間、`.htaccess`
  - `setUp` / `tearDown` を使わない。テストでは、日付に依る値に `FrozenClock` を使う
  - コミットメッセージの末尾に `Co-Authored-By` を付ける
  - Psalm errorLevel 1、Pint
- DB の形は変えない（マイグレーションを足さない）。v0.1.5 から上げたときに「DB の更新」を押さなくて済むようにするため
- 依存を増やさない
- 画面と案内の文言は、各タスクに書いたとおりにする
- `src/php-version.php`、`public/index.php`、`bin/cron.php` は、ファイル全体が PHP 5.5 以降で構文を読めること（計画 10 では 7.0 以降だった）。使わないもの：
  - 引数と戻り値の型、nullable 型、矢印関数
  - `(require …)(…)` のような、式の結果をそのまま呼ぶ書き方
  - `??`、`?->`、名前つき引数、`match`、`never`、型つきのプロパティ
- 5.5 にしたのは、`bin/cron.php` の後半が `::class`（5.5 から）を、`public/index.php` が `[]`（5.4 から）を使うため。そこまで書き直すと手間に見合わない。`(require …)(…)` を直した写しは、さくらの 5.6 で 2 ファイルとも読めた（5.4 は `bin/cron.php` が読めない）
- PHP 5.4 以前では案内は出ない（構文エラーになる）。PHP 5 で表示が有効なら、`declare(strict_types=1)` の警告が 1 行先に出る（さくらの 5.3・5.6 で確かめた）。案内は出るので、そのままにする

## Review Focus

- 画面の PHP は 8.3 で、cron に登録した php だけが古い → cron は「cron に登録したコマンドで…」と案内し、画面は今までどおり（Task 1）
- `public/` の中身だけを公開ディレクトリに置き、`rebuji-root.php` で本体を指す構成 → 画面の案内が出る（Task 1）
- PHP 5.5〜8.2 で入口を読む → 構文エラーにならず、画面の入口は案内を出し、cron は案内を出して終了コード 1（Task 2 の CI ジョブ）
- 間違ったパスワードでログインを試す → ハッシュは書き換えない（Task 4）
- ハッシュがもう今の既定の強さ → ログインしても書き換えない（Task 4）
