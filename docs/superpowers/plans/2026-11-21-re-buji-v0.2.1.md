## Global Constraints

- 計画 1〜15 の Global Constraints をすべて引き継ぐ。主なもの：

  - `setUp` / `tearDown` を使わない。テストでは、日付に依る値に `FrozenClock` を使う
  - コミットメッセージの末尾に `Co-Authored-By` を付ける
  - Psalm errorLevel 1、Pint
  - `src/php-version.php`、`public/index.php`、`bin/cron.php` は PHP 5.5 以降で読める構文のまま（このタスクでは触らない）
  - SQL は SQLite と MySQL の両方で動く書き方にする
- DB の形は変えない（マイグレーションを足さない）。v0.2.0 から上げたときに「DB の更新」を押さなくて済むようにするため
- `umask()` は呼ばない。プロセス全体の値で、スレッドを使う SAPI では他の要求にも効くため
- 今ある DB・ログ・設定ファイルの権限は変えない（新しく作るときだけ `0600`）。web と cron が別のユーザーで動くサーバーで、今まで読めていたものが読めなくならないように
- 画面の文言は、各タスクに書いたとおりにする

### Task 3：秘密の入ったファイルを、初めから 0600 で作る

**Files:**
- Create: `src/PrivateFile.php`
- Modify: `src/Config/ConfigFile.php`（`save()`）、`src/Install/InstallKey.php`（`ensure()`）、`src/Log/FileLogger.php`（`log()`）、`src/Database/Database.php`（`sqliteFile()`）
- Test: `tests/PrivateFileTest.php`（新規）、`tests/Config/ConfigFileTest.php`、`tests/Log/FileLoggerTest.php`、`tests/Database/DatabaseTest.php`

**Interfaces:**
- `ReBuji\PrivateFile::create(string $path): bool`：ファイルが無ければ、空のまま作って（`fopen($path, 'x')`）すぐ `chmod($path, 0600)` する。作れたら true。もうあるか、作れない（フォルダが無いなど）なら何もせず false（今あるファイルの権限は変えない。作れないときの失敗は、今どおり後の書き込みや PDO が伝える）。chmod に失敗したら、作ったファイルを消して `RuntimeException`
- `ReBuji\PrivateFile::write(string $path, string $contents): void`：`create()` で作った新しいファイルに中身を書く。もうあるファイルや、書けないときは `RuntimeException`
- `ConfigFile::save()`：一時ファイルを `PrivateFile::write()` で書いてから `rename()`。投げる例外の文言は今のまま（`'Cannot write config file: ' . $this->path`）
- `InstallKey::ensure()`：`PrivateFile::write()` で書く。例外の文言は今のまま（`'Cannot write ' . $path`）
- `FileLogger::log()`：追記の前に `PrivateFile::create($this->path)`（例外は握りつぶす。ログで処理を止めない）
- `Database::sqliteFile()`：PDO を開く前に `PrivateFile::create($path)`。`sqliteInMemory()` は変えない。SQLite のジャーナルは DB ファイルと同じ権限で作られる
- 今あるファイルの権限は変えない（Global Constraints）。ロックファイル（`cron.lock`、`migrate.lock`）と、公開の確認の nonce は中身に秘密が無いので変えない

### Task 4：ビルドのスクリプトで、タグを確かめる

**Files:**
- Modify: `bin/build-release.sh`
- Test: `tests/BuildReleaseTest.php`

**Interfaces:**
- 版の確かめ（`src/Version.php says …`）の後、composer の前に、次の 2 つを足す
  - タグ `v$version` があり、それが指すコミット（`git -C "$root" rev-parse -q --verify "refs/tags/v$version^{commit}"`）が `HEAD` と違えば、標準エラーに `tag v$version is at <短いハッシュ>, not HEAD; check out the tag or bump the version` と出して `exit 1`
  - タグが無ければ、何もしない（タグは zip を作った後に付けるため）
  - 追跡しているファイルに保存していない変更があれば（`git -C "$root" status --porcelain --untracked-files=no` が空でない）、標準エラーに `warning: uncommitted changes are not in the zip` と出す。止めない

- [ ] **Step 1: 失敗するテストを書く**

```php
// BuildReleaseTest
#[Test] public function refusesATagThatIsNotHead(): void
// 一時ディレクトリに bin/build-release.sh と src/Version.php を写し、git init
// git -c user.name=t -c user.email=t@example.com -c commit.gpgsign=false commit（1 つ目）→ git tag v{Version::CURRENT}（軽量のタグ）
// もう 1 つコミット（空のコミットでよい）
// 写した bin/build-release.sh を Version::CURRENT で動かす
// → 終了コード 1、出力が '/^tag v\S+ is at [0-9a-f]+, not HEAD;/m' に合う、build/ に zip が無い
```

一時ディレクトリは `TemporaryDirectory` で作り、`finally` で消す。タグが無いときと、変更があるときの警告は、composer まで進むので、テストではなく Step 4 で手で確かめる。

`Migration` の docblock の終わりに、次の段落を足す（英語、ほかの docblock と同じ書き方）。

> On SQLite, a migration runs inside a transaction (see Migrator), where `PRAGMA foreign_keys = OFF` does nothing. A migration that rebuilds a table by dropping it would fire `ON DELETE CASCADE` and delete the rows that point at it (dropping `notifications` deletes their replies and messages). Rebuild a referenced table without dropping it, or turn the pragma off outside the transaction first.
