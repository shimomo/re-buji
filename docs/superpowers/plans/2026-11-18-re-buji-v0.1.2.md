## Global Constraints

- 計画 1〜6 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、SQLite の PRAGMA、UTC の時刻の文字列、名前空間、`.htaccess`
  - `setUp` / `tearDown` を使わない。テストでは、日付に依る値に `FrozenClock` を使う
  - コミットメッセージの末尾に `Co-Authored-By` を付ける
  - Psalm errorLevel 1、Pint
- DB の形は変えない（マイグレーションを足さない）。v0.1.1 から上げたときに「DB の更新」を押さなくて済むようにするため
- 依存を増やさない。配布物の `vendor/` は 1,800 ファイル以下のまま
- 画面、メール、README の文言は、各タスクに書いたとおりにする
- 「無事」にするのは、無事と確かなときだけ（設計 5.2 の「無事と数えないもの」）。迷うものは「要確認」に倒す

## Review Focus

- 管理者全員のアドレスが一時的に断られる → その問題は送ったことにせず、60 分後にもう一度試す（Task 1）
- 自動応答のヘッダー（`Auto-Submitted: auto-replied`）も持つ開封確認 → 開封確認として扱い、「不在の自動応答だけ」にしない（Task 2）
- 連絡を送ったアドレスから、大文字と小文字だけが違う形で届いた空の返信 → 「無事」のまま（Task 3）
- 送り主のアドレスでしか照合できず、その人の未回答の連絡が 8 日前のものだけ →「照合できなかったメール」になる（Task 3）
- 404 やエラーの画面 → ふつうの画面と同じセキュリティのヘッダーが付く（Task 4）

### Task 2：開封確認を返信と数えない

**Files:**
- Modify: `src/Replies/IncomingMail.php`、`src/Replies/ReplyRecorder.php`、`src/Replies/UnmatchedController.php`、`README.md`、`tests/Support/MailFixtures.php`

**Interfaces:**
- Produces: `IncomingMail::RECEIPT`（`public const string RECEIPT = 'receipt';`）と、コンストラクタの `public bool $receipt`（`$autoReply` の前）
  - `parse()` が開封確認と見なすのは、次のどちらか
    - `Content-Type` が `multipart/report` で、`report-type` が `disposition-notification`
    - MIME 型が `message/disposition-notification` の部分を持つ
  - 開封確認は自動応答にしない（`$autoReply` は false）。宛先不明の判定（`bounceOf()`）は今のまま先に行う

- Produces: `ReplyRecorder` の動き
  - 照合できた開封確認は、`replies` に kind `receipt` の行（本文は先頭 `UNMATCHED_LENGTH` 文字）を残すだけ
  - 連絡は変えない（答え、`replied_at`、`auto_replied_at` のどれも書かない）。再送は続く
  - 照合できない開封確認は、今の流れのまま kind `receipt` で「照合できなかったメール」に並ぶ
- `UnmatchedController::KINDS` に `'receipt' => '開封確認'` を足す
- Produces（テスト用）：`MailFixtures::receipt(string $from, ?string $inReplyTo = null, string $subject = '開封済み: [安否確認 #a1b2c3d4] 地震がありました'): string`

  - 中身は、`text/plain` の部分（「このメッセージは表示されました。」）と、`message/disposition-notification` の部分（`Final-Recipient`、`Original-Message-ID`、`Disposition: manual-action/MDN-sent-manually; displayed`）
  - `Message-ID` を持ち、`$inReplyTo` があれば `In-Reply-To` と `References` も持つ

### Task 3：照合は、送り主のアドレスでは 7 日以内、連絡を送っていないアドレスからは要確認

**Files:**
- Modify: `src/Replies/ReplyMatcher.php`、`src/Mail/MessageRepository.php`、`src/Replies/ReplyRecorder.php`、`tests/Support/QuakeWorld.php`、`README.md`
- Test: `tests/Replies/ReplyMatcherTest.php`、`tests/Replies/ReplyJobTest.php`

**Interfaces:**
- Produces: `ReplyMatcher::__construct(Database $db, MessageRepository $messages, ClockInterface $clock)` と `public const int SENDER_DAYS = 7;`
  - 送り主のアドレスで結び付けるのは、`last_sent_at` が今から `SENDER_DAYS` 日以内の連絡だけ
  - 条件は `n.last_sent_at >= ?`。値は `Time::format($now->modify('-7 days'))`
  - コンテナは自動で組むので、変えるのは `QuakeWorld::matcher()` だけ
- Produces: `MessageRepository::wasSentTo(int $notificationId, string $address): bool`
  - その連絡で送れたメール（`sent = 1`）のどれかの宛先と同じなら true
  - 比べ方は `EmployeeRepository::addressKey()`（大文字と小文字を区別しない）
- `ReplyRecorder` の返信の流れ
  - スレッドか番号で照合し（`$match->by` が `'sender'` でない）、`wasSentTo()` が false のときは、本文の先頭に `'送り主：' . $from . '（連絡を送っていないアドレス）'` を足す。`$from` は送り主のアドレスで、空なら `'不明'`
  - 本文が空でなくなるので、答えは「要確認」になる
  - 設計 5.2 は意図的ななりすましを受け入れる。ただし、転送した先の家族などの空の返信を本人の「無事」にするのは、同じ 5.2 の「無事と数えないもの」の考えに反するので、要確認に倒す（[判断]）

### Task 5：セッション固定に備える
