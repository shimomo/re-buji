- `bin/install.sh` と `bin/upgrade.sh` は触らない

- **[判断]** cron の行は、`FinishStep::submit()`（`installed_at` を書く）より前に足す。`bin/cron.php` は `installed_at` が無いあいだ何もせずに終わる（`bin/cron.php:36`）ので、先に足しても動かない。印を書いた後に残るのは、画面に出す行だけにする。外れていたら、印の後に crontab を書く間に SSH が切れると、cron の無いまま設置が終わる
- **[判断]** 思わぬ例外は `Console::run()` で捕まえ、メッセージと「種類・場所」の 2 行だけを出して、終わりの状態を 1 にする。trace は出さず、ログにも書かない。ログを開く道具（`FileLogger`）が、同じ原因（`storage/` に書けないなど）で失敗しうるため。SSH の画面の 2 行を写せば、報告には足りる。終わりの状態は、PHP の 255 から 1 に変わる。`install.sh` と `upgrade.sh` は状態をそのまま返すだけなので、困らない。外れていたら、調べるのに trace が要るときは、手元で再現することになる
- **[判断]** `shell_exec` が止められているときは、設置を止めずに、打った文字が見える形でパスワードを聞く。設定ファイル（`--config`）が持てるのは DB・SMTP・IMAP のパスワードだけで、管理者のパスワードは問いでしか入れられないため。止めると、そのサーバーでは設置を終えられない。外れていたら、打ったパスワードが手元の端末の画面と履歴に残る
- **[判断]** `escapeshellarg` も使わない。`disable_functions` には `proc_open` などと並んで書かれることがあり、cron の行を作る `Crontab::line()` は crontab を使えないときにも呼ばれるため。代わりに自分で `'…'` で囲む（POSIX の `escapeshellarg` と同じ出力）
- **[判断]** 画面の仕上げの例 `*/5 * * * * php …` は変えない。書き方の例で、手順書の例と `bin/console install` の既定（5）も 5 分のため
