## Global Constraints

- 計画 1〜7 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、SQLite の PRAGMA、UTC の時刻の文字列、名前空間、`.htaccess`
  - `setUp` / `tearDown` を使わない。テストでは、日付に依る値に `FrozenClock` を使う
  - コミットメッセージの末尾に `Co-Authored-By` を付ける
  - Psalm errorLevel 1、Pint
- DB の形は変えない（マイグレーションを足さない）。v0.1.2 から上げたときに「DB の更新」を押さなくて済むようにするため
- 依存を増やさない。Symfony の `@internal` のクラス（`SocketStream` など）は使わない
- 画面と README の文言は、各タスクに書いたとおりにする

## Review Focus

- 初期設定のメールの段で、管理者のアドレスが一時的に断られる → 500 にせず、理由を出して同じ段にとどまる（Task 1）
- テストメールへの本物の返信より先に、自動応答や開封確認が届いている → 返信の段は進まず、本物の返信が届けば進む（Task 2）
- 遅いフィードの取得の最中に、管理画面から保存する（別の接続から書き込む）→ 待たされずに書ける（Task 3）
- 電文の保存に失敗した回の後 → 次の回に、その電文をもう一度受け取る（「見た」の印が残らない）（Task 3）
- 応答しない SMTP サーバー → 15 秒ほどであきらめる。その後、PHP の `default_socket_timeout` は元の値に戻っている（Task 4）

### Task 3：フィードの取得の間は、DB を押さえない

**Files:**
- Modify: `src/Feed/DatabaseStateStore.php`、`src/Feed/FeedJob.php`、`tests/Support/FakeJmaServer.php`、`tests/Feed/DatabaseStateStoreTest.php`
- Test: `tests/Feed/DatabaseStateStoreTest.php`、`tests/Feed/FeedJobTest.php`

**Interfaces:**
- Produces: `DatabaseStateStore` の書き込みは、`flush()` まで手元にためる
  - `markSeen()` と `save()` は、手元にためるだけで DB に書かない
  - `isSeen()` と `load()` は、手元にためたものを先に見て、無ければ DB を読む
  - `public function flush(): void`：ためた書き込みを DB に書き、手元を空にする
  - `public function discard(): void`：ためた書き込みを捨てる
  - `purge()` は今のまま、すぐに DB を消す
- `FeedJob::run()` の流れ
  1. トランザクションの外で `poll()` する。HTTP の間は、DB の読み取りも 1 文ずつ終わる
  2. 電文の保存と `$this->store->flush()` を、1 つの `$this->db->transaction()` で行う
  3. 1 か 2 が例外を投げたら、`$this->store->discard()` を呼んでから投げ直す。保存に失敗した電文は、次の回にまた受け取る
- クラスの docblock は、次のことに書き換える。SQLite の rollback journal では、トランザクション中の読み取りが共有ロックを持ち続け、ほかの接続の書き込みが待たされた末に失敗する。そのため、HTTP の間はトランザクションを開かない
- Produces（テスト用）：`FakeJmaServer::$onRequest`（`public ?Closure $onRequest = null;`）。`sendRequest()` の最初に、あれば呼ぶ

### Task 4：つながらない SMTP サーバーは 15 秒であきらめる

**Files:**
- Modify: `src/Mail/SmtpMailSender.php`
- Test: `tests/Mail/SmtpMailSenderTest.php`

**Interfaces:**
- Produces: `SmtpMailSender::__construct(?SmtpSettings $settings, int $timeoutSeconds = self::TIMEOUT_SECONDS)` と `public const int TIMEOUT_SECONDS = 15;`
  - `send()` は、送る間だけ `ini_set('default_socket_timeout', (string) $this->timeoutSeconds)` にして、`finally` で元の値に戻す
  - Symfony のソケットは、つなぐときに `default_socket_timeout` を読み、その値で接続と読み取りの時間を区切る
  - `SocketStream::setTimeout()` は `@internal` なので使わない
  - クラスの docblock の「60 seconds unless the server changed it」を、この決まりに書き換える
  - コンテナの `new SmtpMailSender($settings->smtp())` は変えない（既定の 15 秒）
  - 15 秒にするのは、cron の 1 回で、返信を読む処理や見張りが、落ちた SMTP サーバーを長く待たないようにするため。画面のテストメールも、PHP の実行時間の上限（多くは 30 秒）より先に答えを返す

- [ ] **Step 1: 失敗するテストを書く**

```php

// $server = stream_socket_server('tcp://127.0.0.1:0')（accept しない＝挨拶を返さない）。ポートは stream_socket_get_name から取る
// $previous = ini_set('default_socket_timeout', '10')（サーバーの設定のつもり）
// → new SmtpMailSender(self::settings($port), 1) の send(self::mail('ok@example.com')) は MailUnavailable を投げる
// → かかった時間は 5 秒未満、ini_get('default_socket_timeout') は '10' のまま
// finally で ini を $previous に戻し、$server を閉じる
```
