# Re:無事 計画 36：画面の見た目（カード、縁、アイコン）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** どの画面でも中身を白いカードに入れ、カードと入力欄・ボタンの縁を見えるようにし、「Re」のアイコンを画面に出して、v0.4.4 を出せる状態にする。

**Architecture:**
- 色は `public/assets/app.css` の `:root` だけで変える。カードの中の箱（枠、開くもの、スマホの幅の表の行）は CSS で平らにする
- アイコンは `templates/layout.php` で出す。ナビのある画面はヘッダーに小さく、`bare` の画面は題の上に大きく
- 各テンプレートで、節を `<section class="card">` で囲む。DB の形も PHP の動きも変えない

**Tech Stack:** 計画 35 と同じ。依存は増やさない。

**Spec:** `docs/superpowers/specs/2026-11-25-re-buji-cards-design.md`（作者が 2026-11-25 に承認）

**前の計画：** `docs/superpowers/plans/2026-11-25-re-buji-v0.4.3.md`（計画 35、PR #41 でマージ済み、v0.4.3 はリリース済み）

## Global Constraints

- 計画 1〜35 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、`setUp` / `tearDown` を使わない、コミットメッセージの末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`、Psalm errorLevel 1、Pint
  - `src/php-version.php`、`public/index.php`、`bin/cron.php` は触らない。DB の形は変えない。`bin/install.sh` と `bin/upgrade.sh` は触らない
- 画面の文は 1 文字も変えない。足すのは HTML の要素と class だけ
- 本体のファイルは足さない（CSS は `public/assets/app.css` だけ、アイコンは今の `public/assets/favicon.svg`）。テストのファイルは足してよい
- 色は設計書のとおり：`--bg:#eef1f4`、`--edge:#d5dbe1`（新しい）、`--field:#7d8892`（新しい）、`--shadow:0 1px 2px rgba(16,24,40,.04)`。`--line:#e3e7eb` とほかの色は今のまま
- アイコン：ナビのある画面（と、`bare` でない画面）は 28px、`bare` の画面は 56px。`alt=""`。URL は `$this->url('/assets/favicon.svg')` に `?v=` と版
- **[判断]** カードの中の枠（`fieldset`）は、テンプレートを直さずに CSS で平らにする（線・影・地・内側の余白を無くす）。設計書の「すでにカードの画面は色の変更だけ」と、「カードの中のカードを作らない」の両方を満たすため。今これに当たるのは、画面の初期設定の「データベース」と「メール」。外れていたら、その 2 画面の枠の見た目が今と少し変わる（枠の題が、カードの中の小見出しになる）
- **[判断]** 知らせのすぐ後に続くボタン（ホームの「確かめた（この警告を消す）」、地震の画面の「送る」「送らない」）は、今のまま地の上に置く。設計書で、知らせは独立した箱のままで、ボタンはその知らせの操作のため
- **[判断]** 画面のいちばん下の「戻る」リンクの段落には `class="back"` を付ける（CSS は付けない）。テストが、地の上にあってよい段落を見分けるため。当たるのは、CSV の取り込みと従業員の追加・編集の「一覧へ戻る」、代理の記録の「ホームに戻る」「地震の画面に戻る」、DB の更新の「ホームへ」、画面の初期設定の仕上げの、エラーのときの段へ戻る 2 つのリンク
- **[判断]** DB の更新の画面は、知らせ（「ほかの画面で…」「DB の更新を当てるまで…」）をカードの前に出し、版・結果・状態・当てる変更・ボタンを 1 枚のカードに入れる。知らせをカードの中に入れないため、今の「版の行の後に知らせ」の順が、「知らせの後に版の行」に変わる
- **[判断]** ホームで、対応中の地震が無く、止まっているか決めることがあるときの「対応中の地震はありません」は、`<div class="card">` に入れる（「異常なし」の緑の箱と同じ場所の、1 行のカード）
- **[判断]** 照合できなかったメールの「選んだメールを消す」は、表と同じカードの、表の上に置く。表の行を選んで使うボタンのため
- **[判断]** 地震の一覧で、遅れて届いた地震の行の中の知らせ（「遅れて届いた地震」）とボタンは、今のまま表のセルの中に置く。行の中の状態で、カードの中の箱には当たらない
- **[判断]** 従業員の追加・編集で、枠の外にある入力（上の「名前」「所属」、下の「メモ」「有効」）は、それぞれ見出しの無いカード（`<div class="card">`）に入れる。設計書の画面ごとの表は「枠はそのまま」とだけ書いて、この 4 つに触れていないが、地の上に入力が残ると「中身をどれもカードに」に反するため。見出しを足すと文が増えるので、見出しは付けない。外れていたら、見出しの無いカードが 2 枚増える
- リリースノートの「上げる」に、公開ディレクトリの `assets/app.css` を置き換えることを書く（リリースのとき。設計書の制約）

```php
/**
 * What sits out of place on a page: text, tables, lists, headings and fields on the ground instead of in a box, and a card
 * inside a card, as "tag: text" lines so a failure names them. A fieldset inside a card is fine: the stylesheet flattens it.
 *
 * @return list<string>
 */
private static function misplaced(string $html): array
{
    $document = new DOMDocument();
    $previous = libxml_use_internal_errors(true);
    $document->loadHTML('<?xml encoding="utf-8">' . $html);
    libxml_clear_errors();
    libxml_use_internal_errors($previous);
    $xpath = new DOMXPath($document);
    $has = static fn(string $class): string => "contains(concat(' ', normalize-space(@class), ' '), ' " . $class . " ')";
    $box = $has('card') . ' or self::fieldset or ' . $has('alert') . ' or ' . $has('calm') . ' or ' . $has('tiles');
    $queries = [
        '//body//*[self::p or self::table or self::ul or self::ol or self::h2 or self::label or self::details]'
            . '[not(ancestor-or-self::*[' . $box . '])][not(ancestor::header)]'
            . '[not(' . $has('back') . ' or ' . $has('progress') . ' or ' . $has('dots') . ')]',
        '//*[' . $has('card') . '][ancestor::*[' . $has('card') . ' or self::fieldset]] | //fieldset[ancestor::fieldset]',
    ];
    // Each query's matches, as "tag: text with spaces squeezed".
}
```
