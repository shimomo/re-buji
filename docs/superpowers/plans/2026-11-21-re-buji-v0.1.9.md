## Global Constraints

- 計画 1〜13 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、SQLite の PRAGMA、UTC の時刻の文字列、名前空間、`.htaccess`
  - `setUp` / `tearDown` を使わない。テストでは、日付に依る値に `FrozenClock` を使う
  - コミットメッセージの末尾に `Co-Authored-By` を付ける
  - Psalm errorLevel 1、Pint
  - `src/php-version.php`、`public/index.php`、`bin/cron.php` は PHP 5.5 以降で読める構文のまま
  - SQL は SQLite と MySQL の両方で動く書き方にする
- DB の形は変えない（マイグレーションを足さない）。v0.1.8 から上げたときに「DB の更新」を押さなくて済むようにするため
- 依存を増やさない。画面の JavaScript は、今ある `onsubmit` の 1 行を書き換えるだけにする
- 画面の文言は、各タスクに書いたとおりにする

## Review Focus

- 消す地震の返信が、2 つの地震の連絡にまとめられている → どちらにも本文が写り、`replies.message_id` の UNIQUE とぶつからない（Task 1）

### Task 1：地震を消す前に、返信の本文もまとめた連絡へ写す

**Files:**
- Modify: `src/Quakes/NotificationRepository.php`（`handOverAnswers()`）、`src/Replies/ReplyRepository.php`、`src/Quakes/EarthquakesController.php`（`delete()`）、`README.md`
- Test: `tests/Quakes/QuakeDeletionTest.php`

**Interfaces:**
- `NotificationRepository::handOverAnswers(int $earthquakeId): array` は、答えを渡した組を返す：`@return list<array{int, int}>`（[答えのある連絡の id, 答えを受け取った連絡の id]）
  - 受け取る連絡は、今と同じ条件（`merged_into_id` がそれを指し、別の地震の連絡で、`state = merged`）。先に SELECT で id を集め、id ごとに UPDATE する（今の UPDATE の条件と同じ結果になること）
- `ReplyRepository::copyShown(int $fromNotificationId, int $toNotificationId): void`：`$from` の返信のうち、地震の画面に出る種類（`IncomingMail::REPLY` と `IncomingMail::AUTO_REPLY`）の行を、`$to` の連絡の行として写す
  - `kind`、`matched_by`、`from_address`、`subject`、`body`、`received_at` はそのまま、`message_id` は NULL、`created_at` は今
  - `message_id` を NULL にするのは、UNIQUE のため（同じ返信を 2 つの連絡へ写せるように。元の行は地震と一緒に消える）
- `EarthquakesController::delete()`：トランザクションの中で、`handOverAnswers()` が返した組ごとに `copyShown()` を呼んでから、地震を消す。`ReplyRepository` を constructor に足す
- README の「この地震の記録を消す」の段落（「…消せます。元に戻せません。」の後）に、次の文を足す
  > その地震の連絡にまとめていた別の地震の連絡がある人は、答えと返信を、その連絡に移してから消します。
