## Global Constraints

- 計画 1〜26 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、`setUp` / `tearDown` を使わない、コミットメッセージの末尾に `Co-Authored-By`、Psalm errorLevel 1、Pint
  - `src/php-version.php`、`public/index.php`、`bin/cron.php` は触らない
  - `docs/superpowers/` へのリンクは GitHub の絶対 URL。`README.md` と `docs/*.md` のリンクは `DocumentLinksTest` が確かめる
- DB の形は変えない（マイグレーションを足さない）
- 文書とコメントの文言は、各タスクに書いたとおりにする
- **[判断]** 計画 12 の 5 は、逆の向きも直す。まとめた側の地震が後から判定し直され、強い読みになったら、まとめた先の連絡にも上げる。どちらも「まとめた連絡のメールに、まとめた地震より弱い震度が出る」同じ失敗のため。外れていたら、作者が頼んでいない直しが 1 つ増える
- **[判断]** まとめた地震の読みで上げるのは、強いときだけ（同じ強さなら、その連絡の地震の読みのまま）。まとめた側の地震が後から弱い読みになっても、まとめた先の連絡は下げない。`DispatchJob` のコメントのとおり、出しすぎより漏らすほうが悪いため。外れていたら、まとめた先の連絡に、まとめた地震の最新の読みより強い震度が残る
- **[判断]** `check` が送ったテストメールの番号は、`system_state` の `check.test_number` に、最後の 1 つだけ覚える（DB の形を変えないため）。外れていたら、`check` を続けて 2 回流したとき、1 回目への番号だけの返信は、照合できなかったメールとして並ぶ

## Review Focus

- その連絡の地震の新しい読みと、まとめた地震の読みが同じ強さ → その連絡の地震の読み（市町村か地域かの印も）のまま（Task 1 `MatchedCityTest::raisesOnlyWhereTheOtherIsStronger`）
- まとめた地震が名前を挙げない市町村 → その連絡の地震の新しい読みのまま。弱くなっても下げる（Task 1 の同じテスト）
- テストメールの番号を覚えていない（`check` を流したことが無い）ときに、件名に `#` のある返信が来る → 今までどおり照合する（Task 2 `readsANumberedReplyAsBeforeWithoutACheck`）
- レンタルサーバー版で、番号だけで照合されるテストメールへの返信が来る → 今までどおり、照合できなかったメールに並ぶ（Task 2 `keepsListingRepliesKnownOnlyByTheirNumberOutsideDocker`）
- ID が読めない行のアドレスが、ファイルの外の人のアドレスと重なる → 今までどおり言わない（だれの行か分からず、本人のアドレスかもしれない）。既存の `EmployeeImportTest::saysOnlyThatTheIdIsWrong` が押さえる
