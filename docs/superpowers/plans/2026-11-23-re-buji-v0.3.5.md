## Global Constraints

- 計画 1〜23 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、`setUp` / `tearDown` を使わない、コミットメッセージの末尾に `Co-Authored-By`、Psalm errorLevel 1、Pint
  - `src/php-version.php`、`public/index.php`、`bin/cron.php` は触らない
  - `docs/superpowers/` へのリンクは GitHub の絶対 URL。`README.md` と `docs/*.md` のリンクは `DocumentLinksTest` が確かめる
- DB の形は変えない（マイグレーションを足さない）
- 画面と文書の文言は、各タスクに書いたとおりにする
- **[判断]** Docker の起動（`bin/console boot`）では、送信の設定が変わったかを見分けずに、起動のたびに `SendingAccount::checkSoon()` を呼ぶ。見分けるには、前の起動の設定を覚えておく必要があり、パスワードから作った値を DB に残すことになるため。代わりに、再起動のたびにログインの確かめが 1 回増える（次の cron の回）。外れていたら、再起動の多い環境で、送信のサーバーへのログインが少し増える

## Review Focus

- 送信の設定が、無い → ある、ある → 無い、に変わる保存 → どちらも「変わった」（Task 2 `SmtpSettingsTest::tellsMissingSettingsApart`）。無いときの確かめは `MailCheckJob` が飛ばすので、害は無い
- パスワードを空のまま保存する（保存済みのパスワードを使い続ける）→ 変わっていない。前倒ししない（Task 2 の既存のテスト `keepsTheCheckScheduleWhenOnlyTheLimitChanges` が、同じパスワードを送る形で押さえている）
- Docker で、送信の設定が無いまま起動する → `checkSoon()` を呼んでも、確かめは飛ばされる。起動は今までどおり通る（Task 3 の既存のテスト `bootsWithBlankMailValues`）
- cron のコンテナだけを再起動する → `boot` は app のコンテナでしか動かないので、前倒ししない。1 時間ごと（失敗中は 30 分ごと）の確かめで見つかるので、テストは足さない
- コードの途中に入った改行しない空白（`1310 100` の形）→ 取り除かず、書いたとおりのコードでエラーに出す（Task 4 `trimsANoBreakSpaceAtEitherEnd` の 2 つめの確かめ）
