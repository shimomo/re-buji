**Tech Stack:** 計画 5 と同じ。依存は増やさない。

**Spec:** `docs/superpowers/specs/2026-11-05-re-buji-design.md`（4 章の判定と取消、5.2 返事の受け取り、5.4 代理回答、6.2 見張り、6.4 バージョンアップ）

Task 7 で版を `0.1.1` にする。

## Global Constraints

- 計画 1〜5 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、SQLite の PRAGMA、UTC の時刻の文字列、名前空間、`.htaccess`
  - `setUp` / `tearDown` を使わない。テストでは、日付に依る値に `FrozenClock` を使う
  - コミットメッセージの末尾に `Co-Authored-By` を付ける
  - Psalm errorLevel 1、Pint
- DB の形は変えない（マイグレーションを足さない）。v0.1.0 から上げたときに「DB の更新」を押さなくて済むようにするため
- 依存を増やさない。配布物の `vendor/` は 1,800 ファイル以下のまま
- 画面、見張りのメール、README の文言は、各タスクに書いたとおりにする

## Review Focus

- 同じ「Message-ID の無いメール」を 2 回読む（印を付ける前に回が止まった、または同じものが 2 通届いた）→ 1 回だけ記録する（Task 4）
- 記録に失敗したメールを、次の回にまた読む →「読めないメール」は 1 件のままで、回は止まらない（Task 4）
- 送信待ちや保留の人に、代理で「要確認」を記録する → その人には送らず、ホームや地震の一覧の送信待ちにも数えない（Task 5）
- 取り消された保留の地震の「送る」を、開いたままだった古い画面から押す → 404 を返し、連絡は動かない（Task 2）
- SQLite で、途中の文で失敗するマイグレーション → 何も残さず、直した後にもう一度当てられる（Task 6）

**Interfaces:**

### Task 6：DB の更新は 1 つずつ、SQLite では 1 件ずつまとめて当てる

**Files:**
- Create: `src/Database/MigrationInProgress.php`
- Modify: `src/Database/Migrator.php`、`src/Container.php`、`src/Admin/DatabaseUpdateController.php`、`templates/admin/database-update.php`
- Test: `tests/Database/MigratorTest.php`、`tests/Admin/DatabaseUpdateTest.php`

**Interfaces:**
- Produces: `ReBuji\Database\MigrationInProgress extends RuntimeException`
- Produces: `Migrator::__construct(Database $db, list<Migration> $migrations, ClockInterface $clock, ?string $lockPath = null)`
  - 鍵のファイルがあれば、`migrate()` はそのファイルの排他の flock を取ってから `pending()` を読み、当てる。flock の取り方は `CronRunner` と同じ（`fopen` の `'c'`、`LOCK_EX | LOCK_NB`）
  - ほかの更新が鍵を持っていれば、`MigrationInProgress` を投げる
  - SQLite では、1 件の文と `schema_migrations` の行を 1 つの `$db->transaction()` で当てる
  - MySQL は今のまま。DDL が暗黙にコミットし、その後の PDO の `commit()` が「There is no active transaction」を投げるため。クラスの docblock もそう書き直す
- `Container` は `new Migrator($db, $migrations, self::clock($c), $paths->storage('migrate.lock'))` で作る（クロージャに `use ($paths)`）。初期設定の `DatabaseStep` は鍵なしのまま
- `DatabaseUpdateController::apply()` の動き
  - `MigrationInProgress` を捕まえ、`'busy' => true` で描く。`show()` と、ふつうの `apply()` は `false`
  - 描くときの文言：`<p class="warning">ほかの画面で DB の更新が進んでいます。少し待ってから、この画面を開き直してください。</p>`
  - そのときは、版の行と「ホームへ」だけを出す。変更の一覧とボタンは出さない
