## Global Constraints

- 計画 1〜8 の Global Constraints をすべて引き継ぐ。主なもの：
  - PHP `^8.3`、SQLite の PRAGMA、UTC の時刻の文字列、名前空間、`.htaccess`
  - `setUp` / `tearDown` を使わない。テストでは、日付に依る値に `FrozenClock` を使う
  - コミットメッセージの末尾に `Co-Authored-By` を付ける
  - Psalm errorLevel 1、Pint
- DB の形は変えない（マイグレーションを足さない）。v0.1.3 から上げたときに「DB の更新」を押さなくて済むようにするため
- 依存を増やさない
- 画面の文言は、各タスクに書いたとおりにする
- 「近い時間の地震」の規則（設計 4）は変えない：まだ返事をしていない人が、検知が 300 秒以内で `EarthquakeEvent::isPossiblyRelatedTo()` が真の地震でも対象になったら、2 通目は送らず前の連絡に含める

## Review Focus

- 先に送った関連する地震に、その人がもう返信している → 後から「送る」にした地震の連絡は、まとめずに送る（Task 4）
- 先の関連する地震を「送らない」にした → 後から「送る」にした地震の連絡は、まとめずに送る（Task 4）
- テストメールが失敗した → ホームの「メールを送れていません」は、前の理由のまま残る（Task 3）

- フィードの保存が失敗した回 → 電文と「見た」の印のどちらも残らず、次の回にその電文をまた受け取る（Task 1。今の `FeedJobTest::receivesTheTelegramAgainAfterAFailedSave` が守る）

### Task 2：IMAP の TLS が失敗した理由を出す

**Files:**
- Modify: `src/Mail/Imap/ImapClient.php`（`open()`、`startTls()`）
- Modify: `tests/Support/fake-imap-server.php`、`tests/Support/FakeImapServer.php`（オプション `failStartTls`）
- Test: `tests/Mail/Imap/ImapClientTest.php`

**Interfaces:**
- TLS の握手の失敗は、`stream_socket_client()` の `$errorMessage` が空のまま、理由が PHP の warning にだけ出る（PHP 8.5 で確かめた。`ssl://` で平文のサーバーにつなぐと、1 つ目の warning が `stream_socket_client(): SSL operation failed with code 1. OpenSSL Error messages:\nerror:0A00010B:SSL routines::wrong version number`）
- `private static function withWarnings(callable $call): array` を足す。戻り値は `array{mixed, string}`（呼んだ結果と、最初の warning）
  - 呼ぶ間だけ `set_error_handler()` で warning を集め、ハンドラーは true を返す。`finally` で `restore_error_handler()` する。`@` は外す
  - warning は、頭の `関数名(): ` を除き、改行を含む空白の続きを 1 つの空白にする
- `open()` の失敗：`$host . ':' . $port . ' につなげません：' . 理由`。理由は、`$errorMessage` が空でなければそれ、空なら最初の warning、どちらも空なら `'理由は分かりません'`
- `startTls()` の失敗：`'IMAP の TLS を始められませんでした：' . 理由`。理由は最初の warning、空なら `'理由は分かりません'`
- 偽の IMAP サーバーのオプション `failStartTls`：CAPABILITY に `STARTTLS` を足し、`STARTTLS` に `OK Begin TLS negotiation now` と答えた後、平文で `* BYE not really TLS` を送って接続を閉じる

### Task 4：関連する保留の地震を「送る」ときも、前の連絡に含める

**Files:**
- Create: `src/Quakes/QuakeEvents.php`、`src/Quakes/RelatedContacts.php`
- Modify: `src/Quakes/DispatchJob.php`、`src/Quakes/EarthquakesController.php`（`release()`）、`src/Quakes/NotificationRepository.php`、`tests/Support/QuakeWorld.php`
- Test: `tests/Quakes/EarthquakePagesTest.php`（今の `tests/Quakes/DispatchJobTest.php` も通り続けること）

**Interfaces:**
- `ReBuji\Quakes\QuakeEvents`：今の `DispatchJob::event()` と、その `$events` のキャッシュを移す
  - `__construct(TelegramRepository $telegrams, FailedTelegrams $failed, LoggerInterface $logger)`
  - `of(string $eventId, DateTimeImmutable $now): ?EarthquakeEvent`：今の `event()` と同じ（読めない電文はログと `FailedTelegrams::READ` に出す。読める電文が無ければ null。EventID ごとにキャッシュする）
  - `forget(): void`：キャッシュを空にする。`DispatchJob::run()` の始めに呼ぶ（今の `$this->events = []` の代わり）
- `ReBuji\Quakes\RelatedContacts`：今の `DispatchJob::unansweredRelatedContact()` と、まとめる処理を移す
  - `public const int WITHIN_SECONDS = 300;`（`DispatchJob::RELATED_WITHIN_SECONDS` を移す。ほかに使う所は無い）
  - `__construct(QuakeEvents $events, EarthquakeRepository $earthquakes, NotificationRepository $notifications)`
  - `target(int $employeeId, Earthquake $quake, DateTimeImmutable $now): ?int`：今の `unansweredRelatedContact()` と同じ判定で、含める先の連絡の id。`$quake` の地震は `$this->events->of($quake->eventId, $now)` で組み立て、`eventId` が null か、組み立てられなければ null。`DispatchJob::judge()` は、今の `$event` を渡す代わりにこれを呼ぶ（同じ回のキャッシュから同じ地震が返る）
  - `fold(int $targetId, array $cities, int $priority): void`（`$cities` は `list<MatchedCity>`）：今の `judge()` の中の「含める先の市町村に足し、強ければ順番を上げる」処理（`MatchedCity::merge()` と `updateCities()`）。含める先が無ければ何もしない
  - `foldHeld(Earthquake $quake, DateTimeImmutable $now): void`：`$quake` の連絡のうち、状態が `Notification::HELD`、`answer` が null、`employeeId` が null でないものについて、`target()` があれば `fold()` し、`NotificationRepository::markMerged()` で含めた印を付ける
- `NotificationRepository::markMerged(int $id, int $intoId): void`：`state` を `Notification::MERGED`、`merged_into_id` を `$intoId`、`updated_at` を今にする
- `DispatchJob` の constructor は `(Database, TelegramRepository, EarthquakeRepository, NotificationRepository, EmployeeRepository, Settings, LoggerInterface, QuakeEvents, RelatedContacts)`。`FailedTelegrams` は `QuakeEvents` へ移る。判定の結果は今と同じ
- `EarthquakesController::release()` のトランザクションは、`setDelivery(RELEASED)` → `$this->related->foldHeld($quake, $now)` → `$this->notifications->release($quake->id, $now)` の順。含めた連絡は `HELD` でなくなるので、`release()` は残りだけを送信待ちにする。画面の文言は変えない（含めた人は、地震の画面に今までどおり「まとめた」と出る）
- コンテナは自動で組み立てる（PHP-DI の autowire は 1 つのインスタンスを共有するので、`DispatchJob` と `RelatedContacts` は同じ `QuakeEvents` を使う）。`QuakeWorld` は `new` で組み立て直す
