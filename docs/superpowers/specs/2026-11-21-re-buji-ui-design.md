## 1. なぜ整えるか

v0.1.9 までで機能はそろったが、画面は `templates/layout.php` の 10 行ほどのインライン CSS だけでできている。ナビは 8 つのリンクの横並び、ホームの警告は `<p class="error">` の積み重ねで、重さの区別がない。

この製品で一番大事な場面は、**地震のあと、責任者が自宅や避難先からスマホで管理画面を開き、誰を確かめればよいかをすぐ知ること**である。**[決定]** 今の画面はスマホで開くことを考えておらず、ホームには対応中の地震すら出ない。

### 成功とは

- 地震のあと、スマホでホームを開いただけで、どの地震か・返信なしと要確認が何人か・それが誰かが分かる。
- スマホで、親指で主な画面を行き来できる。
- 全画面が同じ見た目にそろい、平時に開いても落ち着いて読める。

### 目標

- ホームに対応中の地震を、案 A の形（6 章）で出す。**[決定]**
- スマホでは画面の下にタブを置く。**[決定]**
- 見た目は「やわらかい」雰囲気（薄い灰色の地に白いカード）にする。**[決定]**
- この見た目を、ログイン・初期設定を含む全画面にそろえる。**[決定]**

### 目標にしないこと

- 電話番号の登録や電話ボタン。**[決定]**
- ダークモード。**[判断]** 今回の範囲を抑えるため。CSS 変数で色をまとめておくので、後から足せる。
- 画面の文言や機能の変更。並びと見た目だけを変える。例外は、6 章のホームの地震の表示と、ホームで操作したあとの戻り先（6.4）。**[判断]**
- 送るメールの見た目（`templates/mail/`）。メールは本文の文字だけで、今回の対象外。**[判断]**

### やってはいけないこと（アンチゴール）

- 色だけで状態を伝えること。色の見分けにくい人や白黒の画面でも分かるよう、必ず印（✕ ⚠ ℹ ✓）と文言を添える。
- レンタルサーバーにそのまま置けなくなること。ビルドの手順、外部の CDN、npm、JavaScript のライブラリを持ち込まない。
- 危険な操作（記録の削除、URL の作り直し、送らない）が、ふつうのボタンと見分けられないこと。
- 地震のあとのホームで、返信なし・要確認の人が警告の山に埋もれること。

## 2. 制約

- PHP のテンプレート（League Plates）。外部の CSS・JS の取り込みはしない。
- `SecurityHeaders` の CSP は `frame-ancestors` / `base-uri` / `form-action` だけで、スタイルとスクリプトは制限していない。今の画面はインラインの `onsubmit` で確かめている。この CSP は変えない。
- `public/.htaccess` は、`public/` にある実在のファイルをそのまま返す。CSS ファイルを `public/` に置けば配信される。公開ディレクトリに `public/` の中身だけを置く設置でも、一緒に置かれる。
- 対象のブラウザは、スマホの Safari と Chrome、PC の Chrome・Edge・Safari・Firefox の最近の版。
- 既存のテスト（PHPUnit）、Psalm、Pint が通ること。

## 3. 見た目の土台

### 3.1 CSS の置き場所 **[判断]**

- `public/assets/app.css` を 1 枚置き、`layout.php` から `<link rel="stylesheet">` で読む。パスは `$this->url()` と同じく、設置先のベースパスを付けて作る。
- `layout.php` のインラインの `<style>` は消す。
- 版が上がったとき古い CSS が残らないよう、URL に `?v=<版>`（`ReBuji\Version`）を付ける。
- 理由：全画面で同じものを使い、ブラウザにキャッシュさせるため。HTML のレスポンスは `no-store` だが、静的ファイルにはかからない。
- リリースの zip（`bin/build-release.sh`）に `public/assets/` が入ることを確かめる。

### 3.2 色と形 **[決定]（雰囲気）／[判断]（値）**

色は `:root` の CSS 変数にまとめる。値は目安で、文字と地のコントラストは WCAG AA（4.5:1）以上を守る。

| 役割 | 変数 | 目安 |
|---|---|---|
| 地 | `--bg` | `#f4f6f8` |
| カード | `--surface` | `#ffffff` |
| 文字 | `--text` | `#26323a` |
| 薄い文字 | `--muted` | `#5f6b74` |
| 線 | `--line` | `#e3e7eb` |
| 操作（リンク・主なボタン・選んだタブ） | `--accent` | `#2b6cb0` |
| 返信なし・止まっている・危険 | `--danger` | `#c0392b` |
| 要確認・要対応 | `--warn` | `#9a5800` |
| 無事・正常 | `--ok` | `#237356` |

文字色に使う 5 色（`--muted` `--accent` `--danger` `--warn` `--ok`）は、`--bg` の上でも 5:1 前後あることを確かめてある。

- カードは白、角丸 12〜14px、影はごく薄く（`0 1px 3px rgba(0,0,0,.08)`）。
- 文字は `system-ui`。本文 15〜16px、行間 1.7。人数の数字は 26〜30px の太字。
- 押せるもの（ボタン、タブ、リンクの行）は、高さ 44px 以上。

### 3.3 部品 **[判断]**

`app.css` に次の部品を用意し、全画面で使う。クラス名は builder に任せるが、意味で名付ける（例 `.card`、`.btn-danger`）。

- **カード**：画面の区切りの基本単位。見出し（`h2`）はカードの外か、カードの頭に置く。
- **ボタン**：主（青の塗り）、ふつう（白に線）、危険（赤の線と赤の文字。押すと今と同じく `confirm()` で確かめる）。フォームの中の送信ボタンはスマホでは横幅いっぱい。
- **警告の帯**：3 段。
  - 止まっている（赤）：`✕` を付ける。連絡が届かない、確かめられないもの。
  - 要対応（橙）：`⚠` を付ける。人の判断を待っているもの。
  - お知らせ（灰）：`ℹ` を付ける。
  - 今の `.error` / `.warning` / `.notice` はこの 3 段に置き換える。フラッシュ（`$this->flash()`）は「お知らせ」か、成功を表す緑（`✓`）で出す。
- **人数のタイル**：数字と名前。色は数字にだけ付ける。
- **人の行**：名前（太字）、その下に薄い文字で所属・市町村と震度・理由・時刻。要確認は本文を「」で囲んで出す。
- **表**：PC では今の表のまま。スマホ（幅 600px 未満）では、1 行を 1 枚のカードにして、列名を各値の前に小さく出す（`data-label` 属性で列名を渡す）。
- **フォーム**：ラベルは欄の上。入力欄はスマホで横幅いっぱい、PC では最大 420px 程度。`fieldset` はカードにする。
- **折りたたみ**（`<details>`）：summary を押せる大きさにし、開閉の印を付ける。

## 4. ナビ **[決定]（形）／[判断]（中身）**

### 4.1 スマホ（幅 768px 未満）

- 画面の下に固定のタブを置く：**ホーム・地震・照合・従業員・その他**。**[決定]**
- タブには小さな印（記号か、インラインの SVG）と名前を付ける。今いる画面のタブを青にする。
- 「照合」のタブには、照合できなかったメールの件数があるとき数字の丸印を付ける。地震のタブには、遅れて届いた地震が待っているとき印を付ける。**[判断]** 判断を待っているものに気づけるようにするため。
- 「その他」は `/more` という別のページにし、**訓練・管理者・設定・DB の更新・ログアウト**を並べる。**[判断]** JavaScript を使わずに作れ、戻るボタンも自然に働くため。
- 上の帯には「Re:無事」と管理者の名前だけを出す。
- タブで本文の下が隠れないよう、本文の下に余白を取る（`env(safe-area-inset-bottom)` も考える）。

### 4.2 PC（幅 768px 以上）

- 下のタブは出さず、上の帯に今と同じ 8 項目を横に並べ、右にログアウトを置く。照合と地震の印はスマホと同じ。
- 本文の幅は最大 760px 程度で、真ん中に寄せる。

### 4.3 ナビを出さない画面

- ログイン、初期設定、エラーはタブもナビも出さない。
- 「DB の更新」の画面（`/admin/database`）は、**更新待ちのときだけ**ナビを出さない。平時に「その他」から開いたときはふつうにナビを出す。**[判断]** 平時に戻る道とログアウトを失わないため。
  - 更新待ちのとき、ナビの件数（照合・遅れた地震）を DB から数えない。古い表に対して数えると壊れるおそれがあるため。代わりにログアウトのボタンだけを画面に出す。

## 6. ホーム

### 6.1 並び順 **[決定]（A の形）／[判断]（警告の置き場所）**

上から次の順に並べる。

1. **連絡そのものが止まる警告**（止まっている＝赤）。
   - 気象庁の情報をまだ一度も確かめていない／15 分以上確かめていない
   - 気象庁の情報の抜け（`feedGap`）
   - SMTP・IMAP の設定がない、返信を読めていない、メールを送れていない
2. **対応中の地震**（6.2）。無いときは「✓ 異常なし」のカード（6.3）。
3. **人の判断を待っているもの**（要対応＝橙）：遅れて届いた地震、照合できなかったメール、判定できない市町村の人、送信待ち、取れなかった・読めなかった電文（「確かめた」のボタンも一緒に）。
4. **お知らせ**（灰）：前回の cron で失敗した処理。
5. 従業員の人数、見張り（状態の URL）。URL を作り直すボタンは危険のボタン。

理由：地震のあとに開いたとき、返信なし・要確認の人を警告の山より先に見せるため。ただし、連絡がそもそも届いていない可能性を示す警告は、人数を読む前に知るべきなので一番上に置く。

### 6.2 対応中の地震 **[決定]（中身と並び）／[判断]（どれを対応中とするか）**

**対応中の地震**とは、次のすべてを満たすもの。**[判断]**

- 検知から 72 時間以内
- 気象庁が取り消していない
- 送る扱い（`auto` か `released`）。遅れて届いて判断待ち（`held`）のものは 6.1 の 3 で扱い、送らない（`dismissed`）ものは出さない。
- 連絡の対象が 1 人以上いる
- 訓練も含める。ただし見出しに「訓練」とはっきり出す。

理由：72 時間は、災害のあとに安否を追いかける期間の目安である。それを過ぎた地震は「地震」のタブから開ける。

対応中の地震ごとに、新しいものを上にして次を出す。

1. 地震のカード：震源・M・最大震度（見出し）、発生時刻、通常か訓練か、対象の人数。カードを押すと地震の詳細へ進む。
2. 人数のタイル 4 つ（2×2）：**返信なし**（赤）・**要確認**（橙）・**無事**（緑）・**対象**（灰）。
3. **⚠ 要確認**の人：名前、返信の本文、「確認済みにする」。
4. **✕ 返信なし**の人：名前、市町村と震度、理由。
5. 無事の人は人数だけ。一覧は地震の詳細で見る。

- ホームでは、要確認と返信なしをそれぞれ最初の 20 人まで出し、それより多ければ「ほか n 人」を `<details>` で開く。地震の詳細は今のまま（返信なしだけ 20 人で切り、要確認は全員）とする。**[判断]** 詳細の動きは変えないため。
- 確認済みの人（`QuakeBoard::build()` の `checked`）はホームの一覧には出さず、要確認のタイルの下に「うち確認済み n 人」と小さく出す。要確認のタイルの数字は、まだ確認していない人だけを数える。返信なし・要確認・確認済み・無事を足すと対象になる。**[判断]** 詳細の画面が今「確認済み n 人」を別に出しているのに合わせるため。
- 縦に長くなるのは構わない。**[決定]**
- 中身は地震の詳細と同じ `QuakeBoard::build()` から作り、部品のテンプレートも共有する。ホームと詳細で数え方がずれないようにするため。**[判断]**

### 6.3 平時

対応中の地震がないときの 6.1 の 2 の場所は、次のとおりにする。**[判断]**

- 6.1 の 1（赤）も 3（橙）もないとき：「✓ 異常なし」と「気象庁の情報を n 分前に確認」を緑のカードで出す。
- 赤か橙のどちらかがあるとき：緑のカードは出さず、「対応中の地震はありません」と灰色の文字で 1 行だけ出す。判断を待っているものがあるのに「異常なし」と出さないため。

ホームの分岐（対応中の地震の有無 × 赤の有無 × 橙の有無）には単体のテストを書く。

### 6.4 ホームで操作したあとの戻り先 **[決定]（ホームに戻す）／[判断]（仕組み）**

ホームで「確認済みにする」を押したら、ホームに戻す。**[決定]** 地震の詳細で押したときは、今と同じく地震の詳細に戻す。

- 戻り先は URL では渡さず、決まった値だけを渡す。フォームの隠し欄 `from=home` があればホーム（`/`）へ、それ以外（欄が無い、知らない値）は今と同じ `/earthquakes/{id}` へ移す。**[判断]** URL を受け取らなければ、外のサイトへ飛ばされる心配がそもそも生じないため。
- ホームの「代理で記録」のリンクにも `?from=home` を付ける。代理回答のフォームはそれを隠し欄で引き継ぎ、記録したあとホームに戻す。入力の誤りで同じフォームを出し直すときも引き継ぐ。**[判断]** 確認済みにするのと同じ流れにするため。
- `ContactsController::backTo()` の変更には、次のテストを書く：`from=home` ならホームへ、欄が無いなら詳細へ、知らない値（`https://example.com` など）なら詳細へ。

## 7. 確かめ方

- 既存のテストが通ること。テンプレートの出力を見ているテストは、文言が変わらない限り通るはずで、通らないものはクラス名などの見た目の変化だけかを確かめて直す。
- ホームの「対応中の地震」の選び方（72 時間、取消、held、dismissed、対象 0 人、訓練）には単体のテストを書く。
- スマホの幅（375px）と PC の幅（1280px）で、ホーム（平時・地震のあと）、地震の詳細、従業員の一覧、設定、ログイン、初期設定の各段階を、ブラウザで開いて目で確かめる。
- 色のコントラストを確かめる。

## 8. builder に任せること

- クラス名、CSS の書き方、ブレークポイントの細かい値。
- タブの印（記号か SVG か）。
- 部品のテンプレートの分け方（`templates/parts/` など）。
- 作業の順番。ただし、土台（`app.css` と `layout.php`）とホームを先にする。
