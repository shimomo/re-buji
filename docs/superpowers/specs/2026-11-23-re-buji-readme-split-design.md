# README の整理：最初の人向けと運用の文書を分ける

## ねらい

README（209 行、約 21KB）に、入れるかを決める人、設置する人、日々使う管理者、上げる人、開発者の内容が混ざっている。作者は、**最初に辿り着いた人が読む部分**と**運用で読む部分**を分け、運用の部分を README の外に置きたい。

- README の仕事：これが何で、自分の組織に合うか、何が要るか、どこから始めるかが、すぐ分かること
- 運用の文書の仕事：設置するとき、使っているとき、上げるときに、することを引けること

## 目標と、しないこと

- 目標：README を、最初の人が上から読み切れる長さにする。運用の内容は 1 つも失わず、`docs/` に移す
- しないこと：運用の文の書き直し。移すときは文を変えず、見出しの深さとリンクだけを直す（レビューを「移しただけ」と確かめられるように）。直すのは、割れていた箇条書き（「メールの設定」）だけ
- しないこと：アプリの動きの変更、アプリの中のヘルプ画面
- 失敗とみなすこと：移した後に、今の README にある説明のどれかが、どの文書からも辿れなくなること

## 案

| 案 | 引き換え | 決め |
|---|---|---|
| **A. リポジトリの `docs/` に Markdown** | 今の PR・レビュー・ルールセットに乗り、コードと同じ版で管理される。目次や検索は GitHub の表示に頼る | **作者が選んだ** |
| B. GitHub の Wiki | ブラウザで直せるが、PR もルールセットも効かず、版とずれる | 選ばない |
| C. GitHub Pages のサイト | 目次と検索があるが、ビルドの仕組みが増え、150 行ほどの内容には重い | 選ばない |

アプリの中のヘルプ画面は、入れる前の人が読めず、コードとテストが要るので外した。

## 形

### README に残すもの（約 70 行の見込み）

1. 題名と紹介の 2 段落（今のまま）
2. NOTE（今のまま。設計書へのリンクは GitHub の絶対 URL にする）
3. **できること**（新しく書く。6 行ほど）：震度で選んで送る、返信するだけ（空なら無事）、再送、責任者の画面、訓練、見張り。各行から `docs/usage.md` の節へリンク
4. 必要なもの（今のまま）
5. **はじめる**：手元で試す（今の Docker の 4 行）、レンタルサーバーに置く（1〜2 行で `docs/install.md` へ）、VPS で動かす（`docs/docker.md` へ）
6. **文書**：`docs/` の各ファイルと中身の表
7. 開発、出典と注意、ライセンス（今のまま）

### `docs/` に移すもの

| ファイル | 中身（今の README の節） |
|---|---|
| `docs/install.md`（新） | 設置（レンタルサーバーに置く）、初期設定、cron、見張りの URL の登録（「見張り」の 1 段落目） |
| `docs/usage.md`（新） | ホーム画面に出ること（「見張り」の残り）、従業員の登録と CSV、メールの設定、地震の連絡、返信と責任者の画面、訓練、記録の削除 |
| `docs/upgrade.md`（新） | バージョンアップ（SSH、0.3.0 までから、FTP、0.2.0 までの権限） |
| `docs/docker.md`（今のまま） | 設計書へのリンクだけ GitHub の絶対 URL にする |

各文書の頭に、README へ戻るリンクを置く。

### 一緒に直すもの

- **リリースの zip**：`bin/build-release.sh` が消すのを、`docs/` 全体から `docs/superpowers/` だけにする。zip の中の README から `docs/` へのリンクが切れなくなり、入れた版と同じ版の説明が手元に残る。`BuildReleaseTest` で、`docs/*.md` が入り、`docs/superpowers/` が入らないことを確かめる
- **設置の画面のエラー文 2 つ**（`KeyStep`、`ExposureStep`）：「…方法（README）」を「…方法（docs/install.md）」にする
- **リリースノートのひな形**：「README の『バージョンアップ』」を「docs/upgrade.md」にする。出した版のノートは直さない

## 私が決めたこと（作者が直せる）

- **設置の手順も `docs/` に移す**：初期設定・cron・見張りは、サーバーで作業しながら読むもので、運用の文書と同じ読まれ方をする。README には始め方の 1〜2 行だけを残す。外れていたら、README から設置の流れが見えにくくなる
- **ファイルは、することごとに 3 つ**（設置、使い方、上げ方）：使い方は 80 行ほどなので 1 ファイルで足りる。GitHub は見出しから目次を出す
- **ファイル名は英語、題名は日本語**：`docs/docker.md` に合わせる
- **`docs/superpowers/` へのリンクは GitHub の絶対 URL**：zip に入らないので、相対リンクだと zip の中で切れる
- **開発の節は README に残す**：最初に辿り着く開発者が読む部分で、10 行と短い

## 作る人に任せること

- 「できること」の文面（今の README の運用の節から、利用者の言葉で短く）
- 各文書の中の見出しの深さと、節の順番の細かいところ
