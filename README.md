# Re:無事（Re:Buji）

地震のあと、従業員に届いたメールに**返信するだけ**で無事を確かめられる、レンタルサーバーに置ける安否確認システムです。BCP（事業継続計画）のために安否確認のツールを入れたいが費用をかけられない組織が、自分のレンタルサーバーに設置して使うことを目指しています。

気象庁防災情報XML（[jmaxml](https://github.com/shimomo/jmaxml-php)）を使います。**非公式**で、気象庁とは関係ありません。

> [!NOTE]
> v0.1 の準備中です。設計書の機能はそろいましたが、まだリリースしていません。設計は [docs/superpowers/specs/2026-11-05-re-buji-design.md](docs/superpowers/specs/2026-11-05-re-buji-design.md) にあります。

## 必要なもの

- PHP 8.3 以上（PDO と、pdo_sqlite か pdo_mysql）
- cron（5 分ごと以上。SSH が無くても、管理画面で PHP ファイルを指定できれば足ります）
- MySQL は無くても動きます（SQLite を使います）
- HTTPS（レンタルサーバーの無料 SSL で足ります）

## 設置

1. [リリース](https://github.com/shimomo/re-buji/releases)から `re-buji-<版>.zip` を取り、展開します。
2. 中の `re-buji/` を FTP でアップロードします。置き方は 2 通りです。
   - **全体を公開ディレクトリに置く**（たとえば `public_html/re-buji/`）。ロリポップのように、公開ディレクトリの外にファイルを置けないサーバー向けです。同梱の `.htaccess` が `public/` の外へのアクセスを拒否します。
   - **本体を公開ディレクトリの外に置き、`public/` の中身だけを公開ディレクトリに置く**。そのときは、公開ディレクトリに置いた `index.php` の隣に、本体の場所を返す `rebuji-root.php` を作ります。

     ```php
     <?php return '/home/ユーザー名/re-buji';
     ```
3. `storage/` に書き込めるようにします（権限 705 か 755）。
4. ブラウザで `https://あなたのドメイン/re-buji/` を開き、初期設定を進めます。

### 初期設定

| 段階 | 内容 |
|---|---|
| 環境の確認 | PHP の版、拡張、`storage/` の書き込みを確かめます |
| 設置の鍵 | 画面を開くと `storage/install-key.txt` ができます。FTP で開き、中の文字列を貼ります。FTP に入れる人だけが設置できるようにするためです |
| データベース | SQLite か MySQL を選びます |
| 最初の管理者 | 名前、メールアドレス、パスワード（12 文字以上） |
| メールの設定 | 送信（SMTP）と受信（IMAP）のアカウント、1 時間の上限、しきい値。保存すると、受信できるかを確かめ、最初の管理者にテストメールを送ります |
| 返信の確認 | テストメールに返信し、その返信を読めたら次へ進みます。ここを通らないと初期設定を終えられません |
| 公開されていないことの確認 | データベースや設定ファイルがウェブから読めないことを、アプリ自身が確かめます。読めてしまうと先に進めません |
| 仕上げ | cron に登録するファイルと、見張りの URL を控えて完了します |

## cron

`bin/cron.php` を 5 分ごとに動かします。**1 分ごとにできるサーバーでは、1 分ごとにしてください。** 地震の情報は cron が動いたときに取りに行くので、5 分ごとだと、最初の連絡が届くまで最大 5 分ほど遅れます。

- **ロリポップ**：管理画面の cron 設定で、プログラムに `re-buji/bin/cron.php` を指定します（エコノミー・ライトは 5 分ごと、スタンダード以上は 1 分ごとにできます）。
- **SSH が使えるサーバー**：`crontab -e` で登録します。

  ```
  */5 * * * * php /home/ユーザー名/re-buji/bin/cron.php
  ```

## 見張り

cron が止まると、地震があっても連絡が送られません。ホーム画面に出る「状態の URL」を、[UptimeRobot](https://uptimerobot.com/) などの無料の監視サービスに登録してください。気象庁の情報を 15 分以上確かめられていない（cron が止まった、サーバーから気象庁に届かない）と、この URL は 503 を返すので、監視サービスからメールが届きます。URL は推測できない文字列を含み、ホーム画面で作り直せます。

ホーム画面には、次のことも出ます。

- 気象庁の情報の抜け（長く止まっていた後など、取りこぼした電文があるかもしれないとき）と、取れなかった、または読めなかった電文。確かめたら「確かめた」で消します
- メールを送れていないこと（設定が無い、サーバーにつながらない、ログインできない）
- 1 時間の上限のために送信待ちの人数と、次に送れる時刻
- 遅れて届いた地震（下の「地震の連絡」）
- 返信を読めていないこと（IMAP の設定が無い、ログインできない、30 分以上読めていない）、照合できなかったメール

画面を誰も見ていなくても気づけるよう、新しい問題が起きると、管理者全員に「[Re:無事] 確かめてほしいことがあります」というメールを 1 回送ります（同じ問題では繰り返しません。消えてからまた起きれば、また送ります）。

## 従業員の登録

管理画面の「従業員」から、1 人ずつ登録するか、CSV でまとめて取り込みます。

- 名前、所属、メールアドレス（1〜4 件。全部に送ります）、市町村（1〜5 件。「勤務地」「自宅」のような呼び名を付けられます）、メモ、有効／停止
- 1 つのメールアドレスは 1 人だけが使えます（返信を送り主のアドレスで照合するため）

### CSV

1 行目は次の見出しにします。「CSV に書き出す」で、この形のファイルを取れます。

```
ID,名前,所属,メール1,メール2,メール3,メール4,市町村1,呼び名1,市町村2,呼び名2,市町村3,呼び名3,市町村4,呼び名4,市町村5,呼び名5,メモ,状態
```

- `ID` が空の行は新しい人として登録し、番号がある行はその人の登録を書き換えます。ファイルに無い人は消えません。
- 市町村は気象庁の 7 桁のコード（例：`1310100` 東京千代田区）で書きます。一覧は従業員の画面の「市町村コードの一覧」から取れます。政令指定都市は、市全体ではなく区のコードです。
- `状態` は `有効` か `停止`（空なら有効）です。
- Excel で保存したファイルをそのまま使えます。Shift_JIS（「CSV（コンマ区切り）」）でも UTF-8 でもかまいません。コードの先頭の 0 が消えていても直します。
- 1 行でも間違いがあれば、何も取り込まず、直すところを行ごとに示します。

## メールの設定

管理画面の「設定」で、送信に使うメールのアカウント（SMTP のサーバー名、ポート、暗号化、ユーザー名、パスワード、送信元のアドレス）と、返信を受けるメールボックス（IMAP）を登録し、「テストメールを送る」と「受信を確かめる」で確かめてください（初期設定で登録した内容が入っています）。

- 送信も受信も TLS の上でだけログインします。STARTTLS を選んだのにサーバーが STARTTLS を使えないときは、パスワードを送らずに止まります。
- IMAP のユーザー名とパスワードが空なら、送信と同じものを使います。
- 送信元のアドレスと、返信を受けるメールボックスは Re:無事 の専用にしてください（`anpi@` のような専用のアドレスを作ります）。ほかのメールソフトやスマートフォンで同じメールボックスを開くと、返信が既読になったり移されたりして、Re:無事 が読みこぼします。
- 返信は、IMAP の設定を保存してから届いたメールだけを読みます。読んだメールには既読の印を付け、消しません。1 回の cron で読むのは 50 通までです。

- 返信を受けるアドレスと**同じアカウント**を使ってください。差出人も、宛先不明で戻ってくるメールの宛先も、このアドレスになります。
- 「1 時間に送ってよい通数」は、サーバーの送信の上限に合わせます（設定の画面に各社の目安があります）。1 人にアドレスが 2 件あれば 2 通と数えます。
- 人数 × アドレスの数が上限を超えると、残りの人には次の時間に送るので、最後の人にはさらに遅れて届きます。安いプラン（ロリポップ エコノミーは 1 時間に 100 通）が向くのは、数十人までの組織です。
- 「.」が続く、または「@」の直前が「.」の古い携帯のアドレス（`taro..yamada@docomo.ne.jp` など）は、そのままでは送れない形なので、`"taro..yamada"@docomo.ne.jp` のように引用符で囲んで送ります。

## 地震の連絡

- 気象庁の震度速報、震源に関する情報、震源・震度に関する情報を使います。気象庁の訓練・試験の電文では送りません。
- 登録した市町村のどれかが「しきい値」（既定は震度 5 弱）以上になった人に、1 つの地震につき 1 通送ります。後から届いた情報で対象が増えたら、増えた人に送ります。震度速報の段階では、市町村の属する地域の震度で判定するので、実際より強めに出ることがあります。
- 返信の無い人には、決まった回数・間隔で送り直します（既定は 3 回・60 分ごと）。件名に【再送】が付きます。
- 気象庁が地震を取り消したら、まだ送っていない連絡は送らず、送った人には「先ほどの連絡は取り消されました。返信は不要です」と送ります。
- 地震から 3 時間（設定で変えられます）より後に情報が届いたとき（cron が止まっていた後など）は、自動では送りません。「地震」の一覧に「遅れて届いた地震」として出るので、送るかどうかをボタンで決めます。送るときは、本文に「○ 時間前の地震です」と入ります。
- まだ返信していない人が、数分のうちの関連しそうな地震でも対象になったら、2 通目は送らず前の連絡に含めます。

## 返信と責任者の画面

- 届いた返信は、まず送ったメールへの返信か（`In-Reply-To`・`References`）、次に件名の番号（`[安否確認 #…]`）、最後に送り主のアドレスで、誰のどの連絡への返信かを決めます。
- 引用を除いた本文が空なら「無事」、何か書いてあれば「要確認」です。言葉で自動に振り分けはしません。引用の下に書いた言葉、書き換えた件名、添付ファイル、読めない文字も「書いてある」と数えます（無事と確かなときだけ「無事」にします）。
- 不在の自動応答と、宛先不明で戻ってきたメールは返信と数えません。自動応答だけの人には再送を続け、戻ってきた宛先は「届かなかった」になります。配信が遅れているという知らせ（まだ送り直している途中）では「届かなかった」にせず、再送を続けます。
- 「地震」の一覧から地震を開くと、責任者の画面です。上から、地震の情報、人数、**返信なし**（理由つき）、**要確認**（本文と「確認済みにする」）、**無事**の順に並びます。
- 電話などで確かめた人は、各行の「代理で記録」で、無事か要確認かとメモを記録できます。記録した管理者の名前も残ります。
- 登録していないアドレスや番号の無い件名からのメールは、「照合できなかったメール」に並びます。本人からの安否の知らせなら、地震の画面の「代理で記録」で記録してください。

## 訓練

管理画面の「訓練」から、全員または選んだ人に訓練の連絡を送れます。件名に【訓練】が付き、本文の先頭に「これは訓練です。」と入ります。送り方や再送は本番と同じで、「地震」の一覧に訓練として出ます。

## 記録の削除

地震の画面の下の「この地震の記録を消す」で、その地震の連絡、送ったメール、返信、気象庁の電文を消せます。元に戻せません。照合できなかったメールは、その一覧の「消す」で消します。

## バージョンアップ

新しい zip の中身を FTP で上書きします（`storage/` は上書きしません）。そのあと、管理画面の「DB の更新」を開いて、ボタンを押します。

## 開発

```bash
composer install
composer test       # PHPUnit
composer analyse    # Psalm
composer lint       # Pint
bin/build-release.sh 0.1.0   # build/re-buji-0.1.0.zip を作る
```

## 出典と注意

出典：[気象庁ホームページ「気象庁防災情報XMLフォーマット」](https://xml.kishou.go.jp/)

- Re:無事 と jmaxml は気象庁の公式のソフトウェアではありません。内容の正確さや速さは保証しません。
- 気象庁の公開のフィードには、リアルタイムの保証がなく、予告なく止まることがあります。
- 実際の防災の行動は、気象庁や自治体などの公式の発表に従ってください。
