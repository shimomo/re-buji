# リリースノートのひな形

`{…}` を埋め、当てはまらない行は消す。見出しと「確かめたこと」「注意」「出典」の文面は、版をまたいで同じにする。`{件数}` は「変わったこと」の箇条書きの数（開発者向けも数える）。

```markdown
{前の版} の後に見つかった {件数} つを直した版です。機能は足していません。

## 変わったこと

- **{利用者から見た名前}**：{今の動き}。前は、{前の動き}
- 開発者向け：{利用者に見えない変更}

## {前の版} から上げる

`re-buji-{版}.zip` を展開し、中身を上書きします（`storage/` は上書きしません）。DB の形は変わらないので、「DB の更新」を押す必要はありません。ログインしている人がログアウトされることもありません。

- SSH で入れるサーバーでは、`sh ~/re-buji/bin/upgrade.sh` で、zip を取るところから上書きまでを済ませられます（[docs/upgrade.md](https://github.com/shimomo/re-buji/blob/main/docs/upgrade.md)）
- 新しいファイルが加わります：{足したファイル}。`vendor/composer/` の中も変わるので、`src/`・`templates/`・`vendor/` は、まとめて上書きしてください
- `public/` の中身（`index.php`、`assets/`）は変わっていません
- Docker で動かしている場合は、`REBUJI_VERSION` を `{版}` に上げて、`docker compose pull && docker compose up -d` を実行します
- `scp` や `rsync` で上げる場合、この zip のフォルダの権限は 755、ファイルは 644 です

## 確かめたこと

- CI では、PHP 8.3・8.4・8.5 と SQLite でテストを動かしています。MySQL 8.4 では PHP 8.3 で動かしています。古い PHP（5.5〜8.2）での案内も確かめています
- ロリポップなど、さくらのレンタルサーバ以外のサーバーでは、まだ試していません

## 注意

- 気象庁の公式のソフトウェアではありません。内容の正確さや速さは保証しません
- 実際の防災の行動は、気象庁や自治体などの公式の発表に従ってください

出典：[気象庁ホームページ「気象庁防災情報XMLフォーマット」](https://xml.kishou.go.jp/)
```

## 「上げる」の節を変えるとき

- **マイグレーションがある**（`migrations/` に足したファイルがある）：「DB の形は変わらないので…」の文を、「上げた後、管理画面で『DB の更新』を押してください。押すまで、管理画面と cron は止まります。」にする
- **新しいファイルが無い**：1 つ目の箇条書きを「新しいファイルはありません。`vendor/composer/` の中は版ごとに作り直すので、`src/`・`templates/`・`vendor/` は、まとめて上書きしてください」にする
- **`public/` が変わった**：「`public/` の中身だけを公開ディレクトリに置いている場合は、公開ディレクトリの {ファイル} も置き換えてください」を足す
- **利用者が手ですることがある**（権限を直す、CSV を取り直す、など）：その手順を、箇条書きの最後に足す
